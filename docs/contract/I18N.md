# Ready for other languages: strings, the check, and formatting

Status: **design for M1 builders**, 09/10/2026. BETA-PLAN arch change 5:
English only for the beta, but "no user-visible text in code … each
platform's normal mechanism … English as the source language, plurals
handled, room for longer languages … frequencies always show in MHz/kHz
with a locale-correct decimal separator"; and gate 1: "a check fails on any
user-visible string literal outside the catalogs (allow-listed exceptions
only)". **[guess]** marks the unverified.

Today nothing is externalised: no `tr()` and no `.ts` file in `openhamshack-nb`,
`openhamshack-atv`, `openhamshack-datv` or `openhamshack-teletext`, and one string in
Remote's Android `strings.xml` (counted 09/10/2026). The one existing
discipline worth keeping is `ohscore`'s: **every sentence whole, names put in
by `format()`, never built from fragments**, "so a later translation can
take each one whole" (`~/openhamshack-nb/ohscore/countries.py`, `ohsradio/guard.py`).

## 1. The rule

1. No user-visible text in code. Everything a person can read (labels,
   buttons, menus, tooltips, dialogs, errors shown to a user, notifications,
   pad faces, server `error` sentences) comes from a catalog.
2. **English is the source language.** The English text lives in the source
   catalog (or is the message id, where the mechanism works that way).
3. **Whole sentences with named placeholders.** `"{app} has the {device}"`,
   never `app + " has the " + device`. Word order differs between languages.
4. **Plurals through the mechanism's plural support**, never `n == 1 ? … : …`.
5. **Room to grow.** Layouts take labels 40% longer than English without
   clipping (German and Finnish run long); pad faces have a hard budget of 7
   characters a line, stated to translators in the catalog comment.
6. **Numbers, dates and units through the formatting helpers** (§4), never
   `str(x)`, `f"{x:.3f}"` or string concatenation with a unit.
7. **Not translated, ever:** callsigns, Maidenhead locators, ADIF field names
   and values, mode names as identifiers (`FT8`, `USB`), protocol strings,
   log file contents. They are data.
8. **Machine-facing text is not user text:** log lines, exception messages
   that never reach a person, JSON keys, error `code`s. Server `error`
   sentences *are* user text (clients show them): they come from the
   server's catalog, and clients prefer their own translation of the `code`
   (CONTROLLER-CONTRACT.md §9).

## 2. Mechanism per platform

| Where | Mechanism | Source catalog | Plurals |
|---|---|---|---|
| **PyQt6 apps** (QO-100 NB, Radio, ATV with Teletext, DATV) | `self.tr("…")` in `QObject` subclasses, `QCoreApplication.translate("Context", "…")` elsewhere in UI code | `<pkg>/i18n/<app>_en.ts`, extracted with `pylupdate6`; compiled `.qm` (`lrelease`) packed into the app | `self.tr("%n stations heard", "", n)` |
| **Python outside Qt UI** (engines such as `ohscore`, app servers, `shack_client`, `shack_bandplan`, `shack_pad`) | stdlib `gettext`, one domain per package (`shack-bandplan`, `ohscore`, `shack-qo100wb`) | `<pkg>/locale/<domain>.pot`, extracted with `pybabel extract`; `.mo` compiled at build (Babel is a build dependency, not a runtime one) | `ngettext`; `pgettext` where the same English means two things |
| **Web UIs** (QO-100 WB console, Icom, Flex, Digital Modes front ends; the controller's own pages) | HTML `data-i18n="key"` and `data-i18n-attr="title:key;placeholder:key2"`; JS `t("key", {params})` from `shack-i18n.js` (our own few-hundred-line loader in `ohs-libs/js`, copied into each app at build: no external assets) | `static/i18n/en.json` | `{"stations": {"one": "{n} station", "other": "{n} stations"}}` chosen with `Intl.PluralRules` |
| **Android** (Remote, every kind, TV mode) | `stringResource(R.string.…)` in Compose, `getString` elsewhere | `res/values/strings.xml` per module (`:core`, `:kind-*`) | `<plurals>` and `pluralStringResource` |
| **Apple** (iPhone, iPad, Apple TV) | SwiftUI string literals are `LocalizedStringKey` and extracted by Xcode; `String(localized:)` outside SwiftUI; `Text(verbatim:)` only for data (callsigns, frequencies already formatted) | `Localizable.xcstrings` (String Catalog) per target, and in Swift packages with `defaultLocalization: "en"` | catalog plural variations |

Rules that cut across:

- **Libraries translate their own sentences.** `shack_bandplan` returns a
  verdict with `code`, `params` and English `text` (BANDPLAN-DATA.md §6.2);
  `bp.translate(verdict, locale)` gives the sentence in a language it has. A
  Qt app calls that, it does not re-translate the English. Dataset text
  (regime notes, plan labels) is extracted into the `shack-bandplan` domain at
  build time from the JSON.
- **Pad faces** are translated by the app that sends them (CONTROLLER-PAD.md
  §6.1); action labels are catalog keys in `pad-actions.json`.
- **Locale choice:** the operating system's (or browser's) locale, with an
  app setting to override. The beta ships `en` only; the machinery must
  still load a second catalog, and a test proves it (§5).
- **Catalog layout is fixed per platform** so tools and translators find
  them: the paths above, English file always present, one file per language.

## 3. The check: `shack-i18n-check`

One tool, in `ohs-libs/python/shack_i18n` (REPO-LAYOUT.md §2), run by every
repo's test suite and CI:

```
shack-i18n-check [--config .i18n-check.toml] [paths…]
```

Exit 0 when clean; 1 with one line per finding:

```
ohsnb/ui/window.py:212:31: user-visible literal "Transmit blocked" passed to QLabel.setText; use self.tr()
android/kind-icom/src/main/java/…/IcomScreen.kt:88:18: literal "Tune" passed to Text(); use stringResource()
```

### 3.1 What counts as a user-visible literal

A string literal (or the literal parts of an f-string / template string)
that contains a run of two or more letters (Unicode letter category) **and**
is passed to a **sink**: an API that puts text in front of a person. Sinks
are listed per language below and extendable per repo in
`.i18n-check.toml`. A literal wrapped in the catalog call (`tr`, `_`,
`ngettext`, `pgettext`, `N_`, `t`, `stringResource`, `String(localized:)`)
is not a finding.

Sink-based rather than "every literal with letters", because the second
flags every dictionary key, CSS class and log line and gets ignored within a
week. The price is that a new UI API must be added to the sink list; the
lists below cover what the family's code uses today.

| Language | How it parses | Sinks (built in) |
|---|---|---|
| **Python** | stdlib `ast` | Qt: `setText`, `setWindowTitle`, `setToolTip`, `setStatusTip`, `setPlaceholderText`, `setTitle`, `setHeaderLabels`, `addItem`, `addItems`, `insertItem`, `setItemText`, `addAction`, `addMenu`, `addTab`, `setTabText`, `showMessage`, `setLabelText`; constructors `QLabel`, `QPushButton`, `QCheckBox`, `QRadioButton`, `QGroupBox`, `QAction`, `QMenu`, `QToolButton`; `QMessageBox.information/warning/critical/question/about`. Servers: the value of an `"error"` key in a dict passed to a JSON response, and `raise` of the exception types the config names as user-facing (`ohscore` raises `ValueError` with user sentences: `licences.clean_custom`). |
| **Kotlin** | a tokenizer that understands comments, `"…"`, `"""…"""` and `${}` templates | `Text(`, `text =`, `label =`, `title =`, `placeholder =`, `contentDescription =`, `Toast.makeText(`, `.setText(`, `.setTitle(`, `.setMessage(`, `NotificationCompat.Builder…setContentTitle/Text(`; plus Android Lint `HardcodedText` and `SetTextI18n` raised to errors in `lint.xml` for XML layouts |
| **Swift** | a tokenizer | `Text(verbatim:` with letters (data only), UIKit `.text =`, `.title =`, `setTitle(`, `UILabel(`, `UIAlertController(title:message:)`, `UNMutableNotificationContent` `.title`/`.body`; SwiftUI literal initialisers are *not* sinks, because the literal is already a catalog key |
| **HTML** | stdlib `html.parser` | text nodes with letters not inside an element carrying `data-i18n`; `title`, `placeholder`, `alt`, `aria-label`, `value` (buttons) attributes with letters not covered by `data-i18n-attr`. Skips `<script>`, `<style>`, `<code>`, `<pre>` and `translate="no"`. |
| **JavaScript** | a tokenizer (strings, template literals, regex literals, comments) | `.textContent =`, `.innerText =`, literal parts of `.innerHTML =`, `.title =`, `.placeholder =`, `alert(`, `confirm(`, `prompt(`, `setAttribute("title" \| "placeholder" \| "aria-label", …)`, `new Notification(`, and functions the repo names (`toast`, `banner`) |

Never a finding: literals with no run of two letters (`"—"`, `"%"`,
`"0.0"`), and literals that are entirely an identifier, path, URL, MIME type
or format spec (`^[a-z0-9_.:/-]+$`, `^%[-+ 0#]*\d*(\.\d+)?[a-z]$`, and a
URL pattern: scheme, `://`, no spaces).

Settled by the first implementation (ohs-libs `shack_i18n`, 09/10/2026):

- The identifier pattern also passes any single lower-case word (`"ok"`,
  `"cancel"`): accepted on purpose, since such strings are far more often
  keys than labels, and a label is usually capitalised.
- §3.3's example entries `"S9+"` and `"fakebox"` can never be findings
  (no two letters in a row; identifier-shaped), so in a real repo they
  would be reported as stale.
- Globs: `*` does not cross `/`, `**` does (plain fnmatch's `*` would make
  `ohsnb/*.py` cover every subfolder).
- Exit 2 when the check cannot run (bad arguments, unknown setting,
  malformed sink); 0 and 1 as above. A file that cannot be parsed is a
  finding, not a pass.
- Android layout and menu XML (`android:text`, `android:hint`,
  `android:contentDescription`, `android:title`) are sinks too, beside
  Lint, so one tool reports everything.
- `.i18n-check.toml` keys: `include`, `exclude`, `allow_list`, and per
  language tables (`[python] sinks`, `user_facing_exceptions`; `[kotlin]`,
  `[swift]`, `[javascript] sinks`; `[html]`, `[android_xml] attributes`).
  Unknown settings are refused, so a misspelling cannot switch a check off.
- Stale allow-list entries, "no English catalog" and unused-key warnings
  are judged only for what the run scanned. Plural translations may drop a
  placeholder but never add one; plain strings need the same set.
- `parse_frequency` refuses anything finer than 1 Hz rather than rounding;
  errors carry a `code` that the vectors compare.

### 3.2 Catalog checks

The same run also checks the catalogs it found:

- every key or message id the code uses exists in the English catalog, and
  every English entry has text;
- plural entries have every form English needs (`one`, `other`);
- each translation's placeholders are the same set as the English
  (`{app}`, `%n`, `%1`, `%@`), so a translation cannot crash a format call;
- unused keys are reported as warnings, not failures (a key used only by
  another platform's kind is legitimate).

### 3.3 The allow-list

One file per repo, `i18n-allow.txt` at the root. One entry per line:

```
# glob | "literal" (exact, JSON-quoted) | reason (required)
ohsnb/ui/smeter.py         | "S9+"     | S-meter scale marking, not language
ohsradio/ui/bandbar.py       | "IBP"     | the NCDXF/IARU beacon project's name
*                         | "QO-100"  | satellite name
android/**/DebugPanel.kt  | "fakebox" | debug build only, never shown to users
```

- Columns separated by `|`; surrounding spaces ignored. The literal is a
  JSON string, matched exactly against the literal's value. The glob is
  relative to the repo root (`fnmatch`, `**` crosses directories); `*`
  alone matches every file.
- **The reason is required.** An entry without one is itself a finding.
- **Stale entries fail**: an entry that matched nothing in a run is a
  finding, so the list shrinks as code changes instead of rotting.
- A shared technical-terms list ships with the tool (mode names `FT8`,
  `FT4`, `JS8`, `CW`, `SSB`, `USB`, `LSB`, `AM`, `FM`, `RTTY`, `SSTV`,
  `DVB-S2`; `QO-100`; ADIF enumerations), so repos do not each re-list
  them. Band names and units are **not** in it: they go through §4's
  helpers.
- No inline "ignore" comments. One file per repo is one place to review
  every exception.

## 4. Locale formatting

Helpers with the same behaviour in every library: Python `shack_i18n.fmt`,
Kotlin `com.openhamshack.i18n.ShackFormat`, Swift `ShackFormat`, JS
`shack-i18n.js` `fmt`. Each takes a locale; the decimal and grouping symbols
come from the platform's CLDR data (`QLocale`, `Intl.NumberFormat`,
`java.text.DecimalFormatSymbols`, `Locale.decimalSeparator`). Pure-Python
servers use a small CLDR-derived table of decimal separators carried in
`shack_i18n` rather than the stdlib `locale` module, which is process-global
and depends on what the host has generated.

### 4.1 Frequencies

| Rule | Example (en / de) |
|---|---|
| Unit is **kHz or MHz** (GHz only where an app chooses it for a 10 GHz display). `auto`: kHz below 30 MHz, MHz from 30 MHz up. An app may fix the unit per field (QO-100 downlinks in MHz). | `14074.0 kHz` / `14074,0 kHz` |
| **Locale decimal separator.** | `10489.750 MHz` / `10489,750 MHz` |
| **No digit grouping, ever.** "10,489.750" and "10.489,750" each read as the other in half the world. | not `10,489.750` |
| Fixed decimals per field: MHz 3 by default (kHz resolution), up to 6 (Hz); kHz 1 by default, up to 3. Trailing zeros kept (a dial does not jump width). | `146.500 MHz` |
| Unit after a no-break space (U+00A0). Unit symbols from the shared catalog (they do change in some scripts: Russian `МГц` **[guess: confirm per language when one is added]**). | `437.000 MHz` |
| Offsets and audio tones in Hz, signed where it is a shift. | `+1500 Hz`, `−600 kHz` (U+2212) |

Parsing what a person types: accept `.` or `,` as the decimal separator (one
of them, once), ignore spaces and no-break spaces, accept an optional unit
(`Hz`, `kHz`, `MHz`, `GHz`, any case); without a unit use the field's.
Refuse more than one separator. Return integer Hz.

```python
fmt.frequency(10489750000, locale="de", unit="MHz")      # '10489,750 MHz'
fmt.frequency(14074000, locale="en")                     # '14074.0 kHz'
fmt.parse_frequency("10489,750", locale="de", unit="MHz")  # 10489750000
```

### 4.2 Everything else

| Kind | Rule |
|---|---|
| Other numbers (dB, W, SWR, MER) | locale decimal separator; grouping only for counts over 9999 ("12 345 contacts"); fixed decimals per quantity (MER 1, dB 1, SWR 1: `1.5:1`) |
| Units | through the catalog with the number in a placeholder ("{n} dB"), never concatenated |
| Distance | km or miles from the profile's `units` (SERVICES.md §2.1) |
| Dates and times | stored and exchanged as ISO UTC; shown in the profile's `timeDisplay` (UTC by default, labelled UTC, as hams expect), formatted by the platform for the locale (24 h or 12 h as the locale says). ADIF and log files never use locale formats. |
| Callsigns, locators | as given, upper case ASCII; never transliterated or re-cased by locale (Turkish dotted I is the classic trap: use locale-independent upper-casing) |
| Lists | `Intl.ListFormat` / `ListFormatter` / a catalog pattern, not `", ".join` in UI text |
| Direction | not right-to-left in the beta; new layouts use start/end, not left/right, so it costs nothing later |

## 5. Tests

1. `shack-i18n-check` runs in every repo's suite and fails it on a finding
   (BETA-PLAN gate 1).
2. A pseudo-locale (`en-XA`: every letter accented, text 40% longer,
   brackets around each string) is generated from each English catalog. One
   UI test per app starts in it and asserts a known label appears
   pseudo-translated and nothing is clipped (screenshot diff where the app
   already takes screenshots). This proves the second catalog loads and
   catches strings that escaped the check.
3. Formatting vectors in `ohs-libs/spec/vectors/i18n/` (locale, Hz, unit,
   decimals → text; text → Hz), run by the Python, Kotlin, Swift and JS
   helpers.
4. A test per server that every `error` sentence it can emit is in its
   catalog (the check covers literals; this covers sentences built from
   catalog entries).
